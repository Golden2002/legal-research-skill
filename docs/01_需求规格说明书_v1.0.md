# 03_法律检索 · 需求规格说明书 v1.0

> 第一波次交付物（2026-08-23）· 基于基线能力清单（03 号文档）+ 顶尖标准对标表（02 号文档）
> 版本 v1.0：需求完整、标准明确、可落地；波次 2 方案论证后升级 v2.0

## 1. 项目定位

**可溯源、零幻觉、全层级、结构化**的法律检索工具：五阶工作流 + 用户分层 + 类案检索 + 权威库接入 + MCP 插件化，可被 PAEG 主 Agent 调度。

## 2. 需求清单（校验用，每条可验收）

### REQ-LR-A 法源权威性

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| LR-A1 | 全层级覆盖：法律/行政法规/司法解释/部门规章/地方性法规/指导性案例 | ≥6 层级目录与检索入口 | P0 |
| LR-A2 | 引用可溯源至权威数据库；标注现行/失效状态 | 溯源字段 100%；状态标注 100% | P0 |
| LR-A3 | 权威库 API 配置接入（北大法宝/威科先行等）+ 扩展接口 | 配置方法文档化；接口可插拔 | P0 |
| LR-A4 | 引用法条为现行有效版本 | 失效法条检测与提示 | P0 |

### REQ-LR-B 检索专业性

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| LR-B1 | 主动信息采集：争议类型/关键事实/管辖地域/时间节点/检索目标 5 要素校验 | 要素缺失主动追问 | P0 |
| LR-B2 | 用户分层：普通人/法学生/专业律师/法官识别与深度粒度适配 | 分层识别 ≥90%；粒度可配 | P0 |
| LR-B3 | 五阶工作流：问题解析→层级检索→冲突适用分析→时效期限梳理→结构化报告 | 5 阶完整可追踪 | P0 |
| LR-B4 | 类案检索：案例匹配/裁判逻辑提炼/争议焦点识别/相关性排序 | 类案按相关性排序输出 | P0 |

### REQ-LR-C 输出标准化

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| LR-C1 | 标准法条引用格式 + 效力层级与适用优先级标注 | 格式合规率 100% | P0 |
| LR-C2 | 推理路径清晰：每条结论对应明确法源依据 | 结论-法源一一对应 | P0 |
| LR-C3 | 无法验证/存疑内容显式标注，不静默编造 | 编造率 0 | P0 |

### REQ-LR-D 插件化与生态

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| LR-D1 | MCP Server：tools/resources/prompts 三原语 | tools/list 动态发现 | P0 |
| LR-D2 | 结构化输出可作为其他工具输入（可组合） | 串联演示 | P0 |
| LR-D3 | 统一错误码/强类型参数/JSON Schema | 契约测试通过 | P0 |
| LR-D4 | 网页端：提问→追问→检索→报告→导出 | 全链路可跑通 | P1 |

### REQ-LR-E 基线保留（能力不退化）

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| LR-E1 | legal-research-skill 全部核心能力保留（速查表/数据库推荐/输出模板） | 反向审计 100% | P0 |
| LR-E2 | 基线输出模板升级为结构化报告模板 | 模板兼容原输出 | P0 |

## 3. 非功能需求

| 项 | 要求 |
|---|---|
| 性能 | 五阶工作流异步可配；检索响应 <30s（无 LLM 排队） |
| 安全 | 无状态；API 密钥环境变量配置不入库；脱敏配置模板 |
| 合规 | 数据源标注来源与更新时间；免责声明 |
| 兼容 | Python 3.10+；独立可运行 |

## 4. 需求校验清单（交付前自查）

- [ ] LR-A1~A4 法源权威性全部可测试（含溯源字段断言）
- [ ] LR-B1~B4 检索专业性可验收（追问/分层/五阶/类案）
- [ ] LR-C1~C3 输出标准化可验收（格式/对应/存疑标注）
- [ ] LR-D1~D4 MCP + 网页端闭环
- [ ] LR-E1~E2 基线 100% 保留（反向审计报告）
- [ ] 每条需求有明确验收标准

## 5. 范围边界（v1.0 不含）

- 不内置完整法条数据库（依赖权威库 API/检索源）
- 不提供法律意见（仅检索与分析，附免责）
- 不做案例文书自动生成
