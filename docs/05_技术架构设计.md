> 波次 2 交付物（2026-08-23）· 依据：基线能力清单（K 域约 100 项）+ 顶尖标准对标表（LR-01~LR-11）

## 1. 总体架构（五层 + MCP 标准件）

```
┌─────────────────────────────────────────────────────────────┐
│ L1 接口层                                                      │
│  Flask API（升级 web/：8 端点→15+）+ 追问交互 + 报告导出        │
├─────────────────────────────────────────────────────────────┤
│ L2 工作流层（五阶引擎）                                         │
│  WorkflowEngine: 问题解析→层级检索→冲突适用→时效梳理→报告输出    │
│  （基线八阶段 SKILL.md 工作流沉淀为可执行引擎）                  │
├─────────────────────────────────────────────────────────────┤
│ L3 服务层                                                      │
│  ProfileRouter（用户分层）│ Collector（5 要素追问）│             │
│  CaseSearcher（类案+排序）│ CitationBuilder（引用格式）│          │
│  TraceBuilder（结论-法源映射+存疑标注）                          │
├─────────────────────────────────────────────────────────────┤
│ L4 内核层（基线 100% 保留）                                     │
│  legal_validator（10 级法源表/效力/时效/引用校验）                │
│  case_retriever（案由词表/争点正则/查询构建）                     │
│  legal_reasoning（演绎/归纳/类比/溯因）                          │
│  use_database_by_api（三适配器：威科/北大法宝/裁判文书网）         │
│  SKILL.md 提示词层（身份分层/引用要素/冲突分析/时效表/报告模板）    │
├─────────────────────────────────────────────────────────────┤
│ L5 数据层                                                      │
│  法源目录（6 层级）│ 案例索引 │ 时效规则库 │ 报告存储             │
├─────────────────────────────────────────────────────────────┤
│ MCP Server（基线 mcp_server.py 9 工具 → 升级 14+）              │
└─────────────────────────────────────────────────────────────┘
```

**设计原则**：基线 L4 内核 100% 保留（validator/retriever/reasoning/DBAdapter/SKILL.md）；五阶工作流引擎把基线"八阶段提示词工作流"升级为可执行、可追踪的编排层；MCP 在基线 9 工具上升级三原语完整。

## 3. 核心接口定义

```
POST /api/legal/research          # 五阶工作流入口
  in:  {question, profile?(auto), facts?:{dispute, facts, region, time, goal}}
  out: {workflow:[{stage, ts, result}], report:{sections, citations:[{source, status, level, priority}]}, unknowns:[], trace:{}}
POST /api/legal/collect           # 信息不全时追问（5 要素）
POST /api/legal/cases             # 类案检索（按相关性排序）
GET  /api/legal/sources           # 法源层级目录（6 层级）
POST /api/legal/db-config         # 权威库 API 配置（脱敏模板）
POST /api/legal/export            # 报告导出（md/html/docx）
```

**存疑标注契约**：每条结论必带 `evidence:[{source_id, status(现行|失效|待核), level, quote}]`；无证据支撑 → `unknown: true` 显式标注，禁止静默编造（LR-09）。

## 4. MCP 插件结构（顶尖标准）

| 原语 | 名称 | 说明 |
|---|---|---|
| Tools | `legal_research(question, facts)` | 五阶工作流（基线 research 工具升级） |
| Tools | `legal_collect_facts(question)` | 5 要素校验追问 |
| Tools | `legal_search_cases(facts, region)` | 类案检索 + 排序 |
| Tools | `legal_validate_citation(text)` | 引用/效力/时效校验（基线 validator 工具） |

| Resources | `legal_sources://{level}` | 6 层级法源目录 |

| Resources | `legal_reports://{id}` | 历史检索报告 |
| Prompts | `legal_research_workflow` | 五阶工作流模板 |

## 5. 数据模型

```
ResearchReport {
  id, ts, question, profile, workflow:[{stage, ts, result}],
  report: {sections:[], citations:[{source, status, level, priority, quote}], unknowns:[], disclaimer},
  trace: {conclusion→evidence 映射}
}
LegalSource { level(法律|行政法规|司法解释|部门规章|地方性法规|指导性案例), name, status(现行|失效), db, updated }
```

## 6. 部署形态

- 独立库（Python 3.10+）+ MCP Server（stdio）+ Flask Web（独立端口）
- 权威库 API：环境变量配置（`LEGAL_DB_*`），敏感信息脱敏模板 `db-config.example.json`
- 可嵌入：被简历/文书工具调用 `legal_research(question)` 校验引用
